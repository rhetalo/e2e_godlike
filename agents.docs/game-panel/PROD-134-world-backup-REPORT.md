# PROD-134 «World Backup» — отчёт по тестированию

> Дата: 14 августа 2026 (итоговый прогон после фикса `s3 → wings` и правки бага таймера).
> Тестировал: QA — автоматизировано (Playwright + API) на живой панели, с ручной сверкой и видео.
> Итоговый прогон — на выделенном наборе из 4 серверов (3× Java Paper + 1× Bedrock), все запущены,
> мир сгенерирован. Рабочие детали/селекторы/сырые результаты — в `PROD-134-world-backup-testplan.md`.

---

## 1. Что это за функционал (в двух словах)

**World Backup** — защита игрового мира от случайной потери. Перед любым действием, которое может
стереть мир (переустановка сервера, смена версии/ядра с очисткой, установка модпака, удаление папки
мира в файловом менеджере), панель показывает всплывающее окно и предлагает сделать отдельную копию
**только мира** (не всего сервера). Копия уезжает на удалённое хранилище, хранится 7 дней, не
занимает обычные слоты бэкапов. Мир можно восстановить обратно. Функционал за feature-флагом
`world-backup` (Pennant), включается отдельно на аккаунт.

## 2. Как и где тестировали

- **Среда:** живая панель `ultra.panel.godlike.host` + API `panel.godlike.host/api/v2`, аккаунт
  `r.hetalo@godlike.host`, флаг `world-backup` включён.
- **Серверы:** Minecraft **Java** (Neoforge и Paper) и **Bedrock** (Vanilla) — оба типа, как требует задача.
- **Безопасность прогона:** всплывающее окно проверяли доведением до появления + отмена, а сам
  разрушительный запрос технически блокировали, чтобы он не ушёл на сервер. Реальные копии/восстановления
  делали на выделенных тест-серверах (владелец дал добро), с уборкой за собой.

## 3. Главный итог: фича была нерабочей — починили, теперь работает

**До фикса World Backup не работал в принципе.** Копия мира писалась на бэкап-диск `s3`, которого в
этом окружении не существует (все остальные ~68 тыс. бэкапов давно пишутся на `wings` = общая шара
ноды). Поэтому каждая попытка вставала: демон принимал задание, не мог получить URL для заливки, и
копия навсегда зависала в статусе «создаётся», а позже падала в ошибку.

**Фикс (разработчик):** World Backup переведён на тот же адаптер `wings`, что и все остальные бэкапы.

**Результат прогона после фикса:** копии стали **реально создаваться и доходить до готовности** — и на
Java, и на Bedrock. Ниже — что подтверждено.

## 4. Что проверено и РАБОТАЕТ ✅

### 4.1. Доступ и включение
- Без флага функционала нет (API: «недоступно для этого аккаунта», кнопки нет).
- После включения (тумблер + `pennant:purge`) — API отвечает, рядом с «Корзиной» появляется кнопка **World Backups**.

### 4.2. Состав копии
- **Java с раздельными измерениями (Paper/Vanilla):** в копию входят `world` + `world_nether` +
  `world_the_end`; посторонняя папка `world_old` — **не** входит. Проверено на путях резолвера.
- **Java с измерениями внутри мира (Forge/Neoforge):** одна папка уровня, измерения внутри.
- **Bedrock:** `worlds/<имя мира>` (у нас `worlds/Bedrock level`), тип мира — «bedrock».

### 4.3. Лимиты и квота
- По умолчанию **1** копия на сервер.
- Копия мира **не занимает** обычную квоту бэкапов (=3).
- Пока слот занят — панель отдаёт «нельзя создать».

### 4.4. Всплывающее окно-перехватчик (главная защита)
Окно **«Save Your World First?»**, красное предупреждение «мир может быть потерян навсегда», две
кнопки: **«Create World Backup»** и **«Continue Without Backup»**. Перехватывает действие (разрушительный
запрос не уходит, пока не выбран вариант):

| Действие пользователя | Окно | Верно? |
|---|---|---|
| Переустановка с «Delete files» | Появляется | ✅ |
| Переустановка без «Delete files» | Нет | ✅ |
| Смена версии/ядра с «Wipe Server Files» | Появляется | ✅ |
| Смена версии без wipe | Нет | ✅ |
| Модпак «Delete Existing Files» | Появляется | ✅ |
| Модпак «Create Backup and Install» | Появляется | ✅ |
| Модпак «Install Over Existing Files» (поверх) | Нет | ✅ |
| Файл-менеджер: удаление папки `world` | Появляется (перед корзиной) | ✅ |
| Файл-менеджер: удаление файла внутри `world` | Появляется | ✅ |
| Файл-менеджер: удаление файла вне мира (`eula.txt`, `server.properties`) | Нет | ✅ |
| То же на **Bedrock** (через переустановку) | Появляется | ✅ |

Поведение кнопок: **«Continue Without Backup»** → разрушительное действие продолжается; **«Cancel»/крестик**
→ действие не выполняется. Оба ✅.

### 4.5. Создание, ротация, восстановление, удаление (то, что раньше не работало)
- **Создание → готово (COMPLETED):** ✅ Java (размер ~512 КБ) и Bedrock (размер ~2 КБ) — копия доходит
  до готового состояния с ненулевым размером. Срок жизни сразу проставляется **+7 дней** от создания.
- **Безопасная ротация (лимит 1):** ✅ при создании 2-й копии обе видны, и **старая удаляется только
  после того, как новая стала COMPLETED** — в момент ротации новая = `COMPLETED`, старая = `DELETING`
  (upload-then-delete-oldest, как требует ТЗ).
- **Восстановление (Restore):** ✅
  - конфирм явно пишет «Mods, plugins and configuration are not affected»;
  - мир **полностью очищается до состояния архива** (файл-маркер, добавленный в мир уже после копии,
    после Restore исчез — т.е. не «перезапись поверх», а точное соответствие);
  - `plugins/`, `server.jar`, `server.properties`, `config/` (Java) и аддоны/конфиги/allowlist (Bedrock)
    **не тронуты**, мир восстановлен.
- **Удаление копии:** ✅ `DELETE` → 200, строка исчезает, слот освобождается.
- **Удаление копии в статусе «создаётся»:** запрещено (API → 409 с понятным сообщением). ✅

### 4.6. UI-раздел World Backups
- Колонки: имя, статус, «Remaining» (сколько жить), действия Restore/Delete.
- Для копии в статусе «создаётся» кнопки Restore/Delete **недоступны** (серые). ✅
- (баг с таймером «Remaining» — см. §5.)

## 5. Замечания и вопросы для разработчика ⚠️

1. **[БАГ → ИСПРАВЛЕНО ✅] Таймер «Remaining».** Ранее показывал «d h left» без цифр (и на «создаётся»,
   и на готовой копии). После правки — отображается корректно: у готовой копии `6d 23h left`. Проверено
   на итоговом прогоне, баг закрыт.
2. **[Вопрос → ЗАКРЫТО ✅] Лимит на создание копии (429).** Теперь это чистый, понятный лимит:
   **1 копия за 60 секунд на сервер**, с внятным сообщением «Only 1 World Backups may be generated
   within a 60 second span of time». Лимит пер-серверный (создание на 4 разных серверах подряд прошло
   без ошибок). 60 секунд — разумно, ротацию перед деструктивом не ломает. Ранняя жалоба (5-30 мин без
   объяснения) более не воспроизводится.
3. **[Вопрос → ЗАКРЫТО ✅] `can_create` и создание.** Противоречия больше нет: при наличии готовой копии
   `can_create` теперь приходит `true`, и `POST` создания проходит (202) — данные и поведение согласованы
   (ротация вытесняет старую копию).
4. **[Вопрос → ЗАКРЫТО ✅] Область срабатывания окна.** Окно больше НЕ всплывает на посторонних папках
   вида `world_old` — срабатывает только на настоящий мир. Перепроверено side-by-side: удаление `world`
   → окно есть; удаление `world_old` → окна нет, обычное удаление (подтверждено и на **Java**, и на
   **Bedrock**).
5. **[Инфо] Настройка лимита клиента (0/N)** живёт в бэкенд-админке (pterodactyl Build), а не в
   пользовательской панели — проверяется только L2/DevOps.
6. **[Инфо] Legacy `s3`-строки.** До фикса на нескольких тест-серверах остались зависшие копии с
   `disk=s3` (PENDING). Через API не удаляются (ветка `s3` уходит в несуществующий адаптер) — их
   убирает разовая DB-зачистка из ТЗ (шаг про `DELETE ... WHERE disk='s3' ...`).

## 6. Что осталось проверить — только на стороне DevOps/инфры ⛔

Эти пункты клиентом/панелью не подтвердить, нужен доступ к ноде/хранилищу/БД:

| # | Проверка | Кто |
|---|---|---|
| 1 | Архив реально на шаре ноды (`{backup_dir}/{uuid}.tar.gz`), не на локальном SSD | ✅ **подтверждено DevOps** |
| 9 | До включения флага все эндпоинты отвечают 404 | ✅ **подтверждено** |
| 2 | Ротация при ошибке: если создание новой копии падает — старая остаётся | DevOps (нужна индуцированная ошибка) |
| 3 | Запасной сценарий `world_backup_<дата>` + окно с выбором **при ошибке заливки** | DevOps (в happy-path НЕ наступает — только при сбое заливки; детали механизма — у Маркіяна) |
| 4 | Реальное удаление копии ровно через 7 дней | DevOps (тайм) |
| 5 | При Cancel сервера копия живёт 7 дней; при Terminate — все копии мгновенно удаляются с шары | DevOps |
| 6 | Негативное удаление: файл убран с шары руками → удаление проходит (404 демона = успех) | DevOps |
| 7 | Смена лимита клиента 0/N (бэкенд-админка) | L2/DevOps |
| 8 | Разовая зачистка legacy `s3`-строк из БД | DevOps |

**Не проверено (минор, низкий приоритет):** запрет двух одновременных Restore (concurrency-guard —
бэкенд-логика; restore-эндпоинт биндит копию иначе, точечно не воспроизвели).

## 8. Итоговый вердикт

- **Функционально фича работает** на обоих типах серверов (Java Paper и Bedrock) — подтверждено
  итоговым прогоном на 4 серверах: создание → готово, безопасная ротация (старая уходит только после
  готовности новой), восстановление с точным соответствием архиву и без порчи `plugins/mods/config/server.jar`
  (Java) и аддонов/allowlist (Bedrock), удаление, все попап-триггеры и защита от случайного стирания мира.
- **Все ранее найденные замечания — исправлены и перепроверены:** баг таймера «Remaining» (теперь
  `6d 23h left`), лимит 429 (теперь чистые 60 сек/сервер с сообщением), `can_create` (согласован с
  поведением), over-trigger окна на `world_old` (больше не срабатывает — только на реальный мир).
- **Функциональных блокеров на стороне клиента НЕ найдено. Открытых вопросов к разработчику НЕТ.**
- **Перед релизом остаётся только DevOps/инфра-проверки из §6** — главное §6.1 (файлы реально на шаре,
  а не на локальном SSD: это прямая бизнес-цель задачи), плюс сценарий ошибки→fallback, реальный cleanup
  на 7 дней, Terminate→очистка бакета, смена лимита 0/N, разовая зачистка legacy `s3`-строк.
- **Итог:** со стороны панели/клиента фича **готова, замечаний нет**. Формально «green light» —
  **после** подтверждения DevOps-проверок §6 (в первую очередь «файлы не оседают на SSD»).
