# Журнал решений (ADR-lite)

> **В двух словах.** Здесь записаны решения по тестам, процессу и документации: что решили, когда, почему и что
> отвергли. Цель - через полгода не гадать «почему так» и не переоткрывать закрытые вопросы. Одно решение = одна
> запись, решения не удаляем: если передумали - новая запись со ссылкой «заменяет D-NNN».
> Источник каждого решения указан: память агента, доки репо или слова владельца с датой.

Формат: **D-NNN · дата · статус** (действует / заменено / на паузе) → решение → почему → что отвергли → источник.

## Агенты и инструменты

### D-011 · 15-Oct-2026 · действует
**Playwright Test Agents - только как ускоритель черновика.** Generator пишет в `tests/agents-pilot/` (проект `agents`,
`default: false`), в рабочие папки - после ревью по `godlike-e2e-conventions`; Healer не меняет ожидания и не ставит `fixme`.
- Почему: в пилоте Generator нарушил 6 конвенций, Planner выдумал баг, Healer «починил» проверку спрятанного элемента.
- Отвергли: автогенерацию прямо в `tests/<domain>/` и автокоммит правок Healer.

### D-013 · 15-Oct-2026 · действует

### D-021 · 16-Oct-2026 · действует
**Контракт API - zod-схемы в `utils/schemas/` (zod 4.6.5, точная версия).** Схема проверяет ВСЕ элементы ответа;
поля контракта строгие, поля оформления допускают `null`, лишние поля не валят. Существующие ручные проверки не удаляем.
- Почему: ручные проверки смотрели только `data[0]`; переименование или смена типа поля при 200 проходили незамеченными.
- Как: `expect(schemaIssues(Schema, json)).toEqual([])` в `test.step`; типы сняты live-пробой 16-Oct, обратная проверка ловит поломку.
- Отвергли: Ajv + JSON Schema (отдельные файлы схем без типов TS), строгие схемы по выборке из 15 элементов.
- Источник: владелец 15-Oct («можно, если ничего не сломает»); `utils/schemas/extensions.ts`.
