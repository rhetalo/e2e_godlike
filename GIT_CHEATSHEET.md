# Git — шпаргалка (для этого репо)

Короткая памятка по веткам/слиянию. Подробное объяснение — в чате; здесь только «под рукой».

## Модель в одну строку

`main` — **чистовик**, всегда рабочий. Любую задачу делаем в **ветке** (черновик рядом),
готовое и проверенное вливаем обратно в `main` через **PR**. `main` руками не редактируем.

## Флоу

```
main   ──●─────────────────────●──   ← чистовик, всегда зелёный
          \                    /
ветка      ●──●──●────────────/       ← тут работаешь, коммитишь, пушишь
       checkout -b   commit ×N    merge (PR)
```

## 5 команд на 90% случаев

```bash
git checkout main && git pull            # 1. взять свежий чистовик
git checkout -b feat/моя-фича            # 2. новая ветка под задачу (+ сразу на неё)
git add -A && git commit -m "что сделал"  # 3. сохранить шаг (коммит ложится на ветку)
git push -u origin feat/моя-фича          # 4. выложить ветку на GitHub
#  5. на GitHub: открыть PR → Merge → затем снова:  git checkout main && git pull
```

После слияния ветку можно удалить:
```bash
git branch -d feat/моя-фича                      # локально (-d безопасно: только если слита)
git push origin --delete feat/моя-фича           # на GitHub
git remote prune origin                          # подчистить устаревшие ссылки
```

## Имена веток (префикс по типу задачи)

| Префикс | Для чего | Пример |
|---|---|---|
| `feat/` | новая функциональность | `feat/game-panel-players` |
| `fix/`  | починка                 | `fix/modded-slider-step-agnostic` |
| `docs/` | только документация     | `docs/git-cheatsheet` |
| `test/` | тесты/эксперименты      | `test/vps-power-actions` |

## Local ↔ GitHub (синхронизация)

| Команда | Что делает |
|---|---|
| `git push` | отправить мои коммиты → GitHub |
| `git pull` | забрать с GitHub → ко мне (fetch + merge) |
| `git fetch` | только посмотреть, что нового, ничего не применяя |
| `git status -sb` | вверху видно `ahead/behind` — на сколько local впереди/позади GitHub |

`## main...origin/main` без чисел = всё синхронно.

## Merge и конфликты

- **Merge** = принести коммиты ветки в `main`.
- **Fast-forward** — если `main` не двигался: просто «догоняет», без отдельного коммита.
- **Merge-коммит** — если двигались обе стороны: git создаёт склеивающий коммит (`Merge: …`).
- **Конфликт** — только если **одни и те же строки** менялись и там, и там. Лечится выбором
  нужной версии руками. Чтобы конфликтов не было — держим разные задачи в разных ветках
  (непересекающиеся файлы → чистый merge).

## Как мы работаем в паре

Агент ответвляется от `main`, коммитит работу в ветку, пушит и даёт ссылку на PR.
Ты смотришь дифф и жмёшь **Merge** (или просишь слить). Потом ветки подчищаются.
`main` всегда остаётся «зелёным».

## Полезное

```bash
git branch -a                  # все ветки (локальные + удалённые)
git branch --merged main       # какие ветки уже слиты в main (их безопасно удалять)
git log --oneline --graph -15  # история коротко, с картинкой ветвления
git checkout .                 # откатить НЕзакоммиченные правки в файлах (осторожно)
```

> ⚠️ Никогда не коммить секреты: `.env`, `storageState*.json`, токены, креды.
