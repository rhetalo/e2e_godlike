# Flaky triage

Цель: по нестабильному тесту принять **обоснованное решение** (фикс / карантин / баг-репорт),
а не глушить `.skip()` и не маскировать `waitForTimeout`/silent-catch. Принцип статей
(testops_tms, OTUS): «сначала трекинг и классификация, потом устранение».

## 1. Собрать сигнал

- Какой тест, как часто падает: всегда / N из M прогонов / один раз. Прошёл ли **только на
  retry** (в CI `retries: 2`) — Playwright помечает такие как `flaky` в отчёте.
- Артефакты: trace (`trace: 'on-first-retry'`), video, скрин, текст ошибки, тайминги.
- Контекст прода: surface, статус сервера, общий аккаунт (мог изменить состояние сосед),
  промо/A-B, headless vs headed (известная разница — смена валюты), **IP/гео** (из UA цена в UAH).
- **Трейс из командной строки** (Playwright ≥ 1.59, проверено на 1.64.1) — без UI, удобно агенту:
  `npx playwright trace open <trace.zip>` → `trace errors` (ошибки со стеком) → `trace actions` (шаги) →
  `trace requests` / `trace console` (сеть, консоль; с 1.61 в трейсе есть и WebSocket — консоль игровой панели) →
  `trace snapshot <action-id>` (DOM на шаге) → `trace close`.
- ⚠️ Ложный флак `ENOENT … .trace`: два параллельных запуска Playwright делят `test-results/` и стирают
  трейсы друг друга. Параллельный запуск — только со своим `--output=<папка>`.

## 1.5 Воспроизвести (burn-in)

Ретраи прячут флак — для диагностики их выключаем:
`npx playwright test <spec> --repeat-each=10 --workers=1 --retries=0 --output=<своя папка>`
- 10/10 зелёных → флак редкий или средовой, смотреть историю прогонов и контекст прода.
- Падает N из 10 → воспроизводится, разбирать трейс упавшей итерации.
- Скрытая зависимость от порядка → добавить `--shuffle`.
- После фикса тот же burn-in обязателен (зелёный 10/10), иначе флак не снят.

## 2. Классифицировать причину

Три корзины (как в `bug-report`, но фокус на стабильности):
- **Тест-баг (наша регрессия)** — гонка (слушатель создан после действия), неоднозначный
  локатор, `waitForTimeout`/`networkidle`, зависимость от другого теста/порядка, expect в
  `catch`. → чинить.
- **Transient среды** — Vue-гидрация (ленивая, нужен mouse-нудж), headless-валюта, panel
  teardown timeout, сетевые лаги, рейт-лимиты. → часто не чинится «здесь и сейчас».
- **Реальный баг прода** — нестабильность из-за самого продукта (нода, 400/Connection
  refused, race на бэке). → не маскировать.

Ранжируй гипотезы по вероятности с шагом проверки (формат `bug-report` §2).

## 3. Развилка решения

- **Тест-баг** → фикс по правилам (`CLAUDE.md`, `TEST_GUIDELINES.md`): web-first ожидания,
  слушатель ДО действия, стабильный локатор из `selectors.ts`, изоляция данных. Снять флоки.
- **Реальный баг прода** → скилл **`bug-report`** (root cause + Jira), запарковать проверку
  в `agents.docs/<surface>/TEST_PLAN.md` («Известные проблемы прода»). Если баг **стабильный** (падает
  всегда, а не через раз) - тест не выключать, а пометить `test.fail(true, "DEV-123: ...")` + `annotation` с тикетом:
  он описывает правильное поведение и сам покраснеет, когда баг починят (тогда пометку снять). `TEST_GUIDELINES.md` §5.8 C2.
- **Transient, не устранимый сейчас** → тег **`@flaky`** + карантин по процессу
  `TEST_GUIDELINES.md` §5.7: вывести из гейтящего прогона (`npm run test:stable`), гонять
  отдельно (`npm run test:quarantine`), и **записать в `test-docs/README.md` → «Текущий
  карантин»** (тест, причина, дата, ссылка). Рядом с тегом — однострочный комментарий ПОЧЕМУ.

## 4. Анти-паттерны (не делать)

- `.skip()` без условия и причины; `force: true` как затычка; `try/catch` глотающий assert;
  увеличение `waitForTimeout` «чтоб не падало». Это маскировка, а не триаж.
- Правка **ожидаемого значения** под текущее поведение прода (текст, число, цена, статус) — это не фикс
  флака, а возможный баг прода. Так же Playwright Healer (`.claude/agents/playwright-test-healer.md`):
  его берём как диагност (причина, локатор), правку ревьюим по `godlike-e2e-conventions` §5.

## 5. Готово, когда

- Причина классифицирована (не симптом), решение принято и применено.
- Карантин — это TODO с дедлайном: либо чиним и снимаем `@flaky`, либо подтверждаем баг.
  Цель — **пустой карантин**. Прод не оставлен в грязном состоянии.
