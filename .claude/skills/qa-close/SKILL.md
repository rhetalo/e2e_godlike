# QA close (закрытие задачи)

Зачем: QA по задаче даёт знание (поведение, API, гочи) и готовый сценарий проверки. Если не сохранить их **в момент
закрытия**, они остаются только в артефакте и Jira-комменте: KB отстаёт, автотестов не прибавляется (разбор 23-Oct-2026,
D-025). `checkpoint` - про сессию, этот скилл - про задачу. Делать по порядку.

## 0. Задача правда закрыта?

- Сигналы: «ОК» в названии чата (ставит владелец), Jira «Готово» или «Ready for Approve», явные слова владельца.
- Jira только читать (`searchJiraIssuesUsingJql` по ключу). Статусы не менять (память jira-write-access).
- Есть открытый ретест или ждём ответа разработчика - карточка `status: partial`, ритуал всё равно проходим.

## 1. Сверка с MR

Все шаги QA из MR + DoD закрыты или явно помечены ⏸️ / ⏭️ с причиной (память feedback-verify-against-mr-steps-before-final).

## 2. KB

Правила - `kb/README.md`, ID и ссылки - `kb/_meta/id-scheme.md`, шаблоны - `kb/_meta/templates.md`.

- **Карточка** `kb/tickets/<KEY>.md`: что изменилось, итог QA, находки `<KEY>/F<n>`, связи, хвосты, **`regression:` + раздел «Регресс»** (шаг 3).
  Первоисточники: Jira-коммент и отчёт в `test-docs/<product>/<KEY>/`, память по задаче. Чего нет - `❓`.
- **Страница фичи** `kb/products/<prod>/<slug>.md`: тикет в `tickets:`, строка в «История», строка в «Покрытие», если поменялось, `updated`.
- **API** `kb/products/up/api/<ресурс>.md`: каждый эндпоинт, который трогал QA (метод, путь, параметры, коды, лимиты, как проверено).
  Новая страница - строка в `api/README.md`. Токены не писать.
- **Реестры:** серверы (переименование, состояние, что оставлено), аккаунты, флаги - `kb/registry/`.
- Параллельно находки по живому DOM - `agents.docs/game-panel/KNOWLEDGE_BASE.md`.

## 3. Регресс-кандидат: решение

Одно значение в шапке карточки + раздел «## Регресс» с причиной и тем, что покрыть.

| `regression:` | Когда |
|---|---|
| `candidate` | поведение стабильное, проверяется на проде без оплаты и регистраций, результат детерминирован |
| `covered` | спек есть: путь и ID теста в разделе «Регресс» |
| `blocked` | покрыть позже: фича ещё не на проде (QA шёл на stage), временный флаг или QA-превью, нужен стенд |
| `no` | в e2e не идёт: суточный бэкенд-обход, разовая миграция без видимого эффекта, письма, регистрации, оплата |

Правила:
- **Автотесты только на проде и на тест-аккаунте** (D-001, D-026). Фича доступна не всем → `blocked`:
  - QA шёл на stage - ждём выкатки на прод;
  - фича под флагом (на админе владельца, у части пользователей, `kb/registry/flags.md`) - ждём раскатки на всех.
    Env-переключатель на весь прод (например `GODLIKE_BEDROCK_NETHERNET_ENABLED`) раскаткой считается.
  При каждом запуске этого скилла пробегись по `blocked` с этими причинами: не доехало ли.
- **Мутации - только на серверах автотестов под мутации** (D-026, `test_e2e_mut-*` в `kb/registry/test-servers.md`,
  env в `utils/gameAuth.ts`), serial, с teardown. Сменить игру или версию под задачу можно. На остальных серверах - read-only.
- Приоритет: read-only контракт API (zod, `utils/schemas`) > read-only UI-структура > мутация на выделенном сервере.
- **Спек ложится плавно - пишем сразу.** Только что пройденные шаги = сценарий; Page Object и селекторы уже есть;
  read-only; ~1 спек или 1-3 теста в существующем спеке. Тогда: план в 2-3 строки (что, куда, что переиспользуем) →
  загрузить `godlike-e2e-conventions` → написать → прогнать спек → `npx tsc --noEmit` → `regression: covered`.
  Нужен новый PO, новый env или мутация - в карточку `candidate` и предложить владельцу отдельным шагом.
- Индекс и бэклог: `python -I kb/_tools/tickets_index.py kb/tickets` (раздел «Бэклог автотестов» собирается сам).

## 4. Проверки

- `python -I kb/_tools/linkcheck.py .` - 0 битых.
- `python -I kb/_tools/frontmatter_check.py .` - 0 ошибок (закрытая карточка без `regression:` - ошибка).
- `python -I kb/_tools/coverage.py . --write` - если менялись `tests:` фич или спеки.
- Если писали спек - сам спек зелёный + `npx tsc --noEmit`.

## 5. Коммит и память

- Коммит kb (+ спек отдельным коммитом) по памяти git-autonomous; `test-docs/` не коммитить (commit-scope-tests-only).
- Память по задаче: итог, что оставлено на серверах, RESUME. Строка в `MEMORY.md`.

## 6. Отчёт владельцу

Одним блоком: что записано в KB, решение по регрессу и почему, спек (если написан, с результатом прогона), что осталось.
