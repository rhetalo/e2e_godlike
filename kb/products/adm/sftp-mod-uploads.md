# SFTP Mod Uploads - кто ставит моды руками по SFTP

> **В двух словах.** Страница админки со списком клиентов, которые сами загружали `.jar` прямо в папку `mods/`
> по SFTP: клиент, сколько серверов, сколько файлов, последняя загрузка, разворот по серверам и файлам. Нужна
> саппорту и продукту, чтобы отличать ручную установку модов от модпаков и установщиков. Описано по проду на 10-Nov-2026.

## Где в интерфейсе
- `panel.godlike.host/admin/sftp-mod-uploads`, пункт меню «SFTP Mod Uploads». Открыта любому админу, отдельного права нет.
- Фильтры: From / To (по умолчанию последние 30 дней), «Client or server» (email, username, имя сервера, начало UUID, ID, external_id).
- Плитки Clients / Servers / Mod jars uploaded, таблица по 25 клиентов, кнопка Files разворачивает файлы по серверам.

## Как работает (под капотом)
- Отдельного детекта нет. Wings пишет каждую SFTP-запись в `activity_logs`: `server:sftp.create`, `server:sftp.write`, `server:sftp.rename`.
  Страница читает только их (actor = пользователь).
- Другие пути пишут свои события и сюда не попадают: веб-менеджер → `server:file.upload` / `server:file.uploaded`,
  вкладка Mods → `server:mod.install`, модпак → `server:modpack.install`.
- Файл считается, если путь подходит под `(^|/)mods/[^/]+\.jar$`. Для rename учитывается только место назначения.
- Одна загрузка = уникальный путь jar на (клиент, сервер, календарный день UTC). Повторы и пара «временный файл → rename» схлопываются.
- Период переводится в диапазон id (индекса по `timestamp` нет) с запасом ±6 ч, потом точный фильтр по времени.

## Правила и граничные случаи
1. **Клиент = тот, кто зашёл по SFTP,** а не владелец сервера. Сабюзер получает свою строку. Поиск по email владельца его загрузку не найдёт, поиск по серверу найдёт.
2. **Не считаются:** `.jar` вне `mods/` (корень, `config/`, `plugins/`), во вложенных папках `mods/sub/`, `.jar.disabled`,
   временные `.filepart` / `.staged` / `.pending` / `.uploading`, незавершённая загрузка без rename.
3. **Считается перенос** `.jar` из другой папки в `mods/` (rename или копия).
4. **Хранение 90 дней** (`activity.prune_days`), старше показать нельзя.
5. **Время в UTC** без подписи зоны ([DEV-678/OBS-2](../../tickets/DEV-678.md#находки)).
6. Валидация: `to` не раньше `from`, даты `YYYY-MM-DD`, поиск до 191 символа, `page ≥ 1`. Ошибка показывается красной плашкой над формой.

## Гочи для тестирования
- Живая SFTP-загрузка на проде - только руками владельца: вводить пароль SFTP от прода Claude нельзя. Сверять по `activity_logs` + странице.
- Wings шлёт события пачками: появление на странице 1-2 минуты, ids не строго по времени.
- 30 дней ≈ 2.6-2.9 с, 90 дней ≈ 11.5 с ([DEV-678/OBS-1](../../tickets/DEV-678.md#находки)).
- Запросы к `activity_logs` только узкие: по `actor_id`, через `activity_log_subjects` по серверу или по id-диапазону.
