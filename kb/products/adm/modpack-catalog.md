# Каталог модпаков v2 в админке - скрытие из клиентского каталога

> **В двух словах.** В админке есть каталог модпаков, которые предлагаются клиентам. Многие модпаки есть и на
> CurseForge, и на Modrinth, и клиент видел их дважды. Теперь админ одной галочкой «Client catalog» убирает
> запись из клиентского каталога и калькулятора на витрине, без деплоя. Серверы, которые уже стоят на скрытом
> модпаке, работают и обновляются как раньше.

## Где в интерфейсе

- Карточка модпака `/admin/modpacks-v2/view/{id}` → чекбокс **«Client catalog»**.
- Список модпаков: колонка **Listed / Hidden**.
- Пулы: страница создания пула `/pools/new` видит и скрытые записи (полный путь в источниках не записан ❓).

## Как работает (под капотом)

- Поле `modpacks_v2.is_listed` ([is-listed](../../registry/flags.md#is-listed)), сохраняется `PATCH .../listing`.
- Действует со следующего запроса: API отдаёт `Cache-Control: no-cache`, Cloudflare `DYNAMIC`.
- Скрытая запись пропадает:
  - из каталога модпаков клиента, `meta.total` уменьшается;
  - из калькулятора на modded-странице витрины (desktop и mobile).
- Скрытая запись остаётся рабочей:
  - detail модпака отдаёт 200 с версиями;
  - серверы на нём ставятся и обновляются;
  - прямая ссылка корзины `modpackId=modrinth:...` открывается (корзина берёт модпак только из ссылки);
  - в каталоге ultra.panel с фильтром Source = Modrinth скрытый модпак находится - так описано в MR.

## Правила и граничные случаи

| Что | Граница | Что видит пользователь |
|---|---|---|
| Значение `is_listed` в PATCH | пусто / `abc` / `5` | 422, в БД ничего не пишется |
| Не-админ открывает страницу админки | - | 403 |
| Запрос без сессии | GET / PATCH | 403 / 419 (CSRF) |

## Не баг - так задумано

| Можно ожидать | Как на самом деле | Почему |
|---|---|---|
| Дубли CF / Modrinth скрываются автоматически | скрытие ручное, по одному модпаку | глобального приоритета CF над Modrinth нет, вне скоупа по договорённости с автором |
| Совпадение имени = дубль | не всегда: Create+ - три разных Modrinth-записи | скрывать только после сверки ([DEV-532](../../tickets/DEV-532.md#находки)/O2) |
| Скрытый модпак не найти нигде | в каталоге ultra.panel по Source = Modrinth находится | так в MR |

## Гочи для тестирования

- **Чекбокс кликать через `label[for=modpackIsListed]`** - label перехватывает клик.
- **После прогона вернуть `is_listed=1`** всем скрытым записям: это живой каталог прода.
- **Order Now в `/cart-modded-new` на проде не жать** - оформляет заказ.
- Любое действие в админке - только с ок владельца ([ADM](README.md#правила)).
- Нескрытых пар по имени 50+ (BMC3 Fabric, BMCS, Cobblemon NeoForge, COBBLEVERSE…): список для скрытия должен дать бизнес (DEV-532/O1).

## Что проверять (минимальный регресс)

| Сценарий | Ожидание |
|---|---|
| Скрыть запись | пропала из каталога клиента и калькулятора витрины, `meta.total` меньше на 1 |
| Detail и сервер на скрытом модпаке | 200, ставится и обновляется |
| Прямая ссылка корзины на скрытый модпак | открывается |
| Невалидный PATCH | 422, в БД без изменений |
| Вернуть запись | снова видна |
