# Параметры запуска в старой панели - выбор образа Docker

> **В двух словах.** На странице «Параметры запуска» клиент видит, на какой Java (образе Docker) работает сервер, и
> может выбрать другую из списка, который разрешает тип сервера (egg). Если образ поставил админ и его нет в
> списке, вместо выбора показана надпись «Образ Docker этого сервера был установлен администратором». С
> 12-Oct-2026 страница всегда показывает актуальный образ, без перезагрузки.

## Где в интерфейсе

- Страница сервера `panel.godlike.host/server/<short>` → меню **«Параметры запуска»** → поле **«Образ Docker»**.
- Варианты списка - из `docker_images` egg, например «Java 8», «Java 21», «Java 17 (libxrender)» (egg 121).
- Выбор сохраняется сразу, без тоста; после F5 остаётся выбранным (DEV-486 U1).

## Как работает (под капотом)

- `GET /api/client/servers/:uuid/startup` отдаёт текущий образ в `meta.docker_image` (с [DEV-513](../../tickets/DEV-513.md)).
  При заходе на страницу существующий `mutate()` синхронизирует образ в сторе.
- Ручная смена образа клиентом - PUT docker-image (T1 в DEV-513 работает); точный путь эндпоинта в источниках не записан ❓.
- Реальное значение образа - `servers.image` в panel DB.
- Образ меняют три пути: клиент здесь, [Version Changer](version-changer.md) при смене версии, админ в [ADM/server-startup](../adm/server-startup.md).

**Почему был баг до DEV-513:** ответ `/startup` не содержал образ; его писал в стор только `getServer()` при монтировании всего
`ServerRouter`, а переход по меню - клиентский роут без перемонтирования. Select стоял на `defaultValue`, поэтому после смены версии
или смены образа админом страница показывала старую Java до F5. Клиент мог «вернуть» её руками и сломать запуск.

## Статусы и переходы

Два режима поля «Образ Docker» (`isCustomImage`):

| Из | Действие | В | Кто |
|---|---|---|---|
| Select (образ из списка egg) | админ ставит `custom_docker_image`, которого нет в egg | Надпись «установлен администратором» | админ ([ADM/server-startup](../adm/server-startup.md)) |
| Надпись «установлен администратором» | админ очищает `custom_docker_image` | Select | админ |
| Select | клиент выбирает другой вариант | Select с новым значением | клиент |
| Select | смена версии через changer | Select с новой Java | клиент ([version-changer](version-changer.md)) |

Все четыре перехода видны при заходе через меню без F5 (DEV-513 T2-T4, A1-A3, 12-Oct-2026).

## Гочи для тестирования

- **Проверять переходом по меню** (Консоль → Параметры запуска), а не перезагрузкой: F5 маскирует баг устаревшего образа.
- **Админку открывать во второй вкладке,** клиентскую не перезагружать, иначе проверка SPA теряет смысл.
- На egg 3 (PC-Paper) libxrender-образа нет в списке - надпись «установлен администратором» там штатная (поведение Pterodactyl), не баг.
- Сверка образа: client API `/startup` (`meta.docker_image`); SQL к panel DB в DEV-513 отклонил классификатор.
- «Файлы versionchanger не тронуты» в DEV-513 проверено только по MR, не UI-путём.

## Что проверять (минимальный регресс)

| Сценарий | Ожидание |
|---|---|
| Клиент выбирает другой образ | сохраняется, после F5 тот же |
| Смена версии → «Параметры запуска» по меню | новый образ без F5 |
| Админ меняет образ во второй вкладке → клиент заходит по меню | новый образ без F5 |
| Админ ставит custom-образ / очищает | надпись «установлен администратором» / снова select |
