# DEV-486 - Старый Version Changer и образы libxrender

> **В двух словах.** У части серверов стоит Java с библиотекой libxrender (она нужна модам, которые рисуют
> картинки, например карты). В старой панели смена версии Minecraft на таких серверах ломалась: панель
> не могла прочитать номер Java из названия образа. Исправили. QA 25-Sep-2026: со всех трёх образов
> (Java 17/21/25 libxrender) смена версии проходит, сервер стартует. PASS.

## Что изменилось
- Номер Java из имени `yolks-javaNN-libxrender` читается верно (раньше как 0 → отказ в смене версии).
- Смена версии через «Изменение версии Minecraft» в старой панели проходит с любого libxrender-образа.
- Changer меняет образ на подходящую Java; если текущая Java подходит, образ не трогает.

## Как это работает
- Старая панель: `panel.godlike.host/server/<short>`, раздел «Ядро & Версия» →
  `POST /api/client/extensions/versionchanger/servers/{uuid}/install {build, delete_files}` → тост «Версия успешно изменена.»
- Образ виден в «Параметрах запуска» → «Образ Docker»; реальное значение - `servers.image`.
- libxrender-образы есть только в eggs 2 (PC-Forge), 121 (PC-Fabric), 1863 (PC-NeoForge); в egg 3 (PC-Paper) нет,
  там образ показан как «установлен администратором».
- Поставить нестандартный образ: Legacy Admin `/admin/servers/view/{id}/startup` → `custom_docker_image`
  (смена egg там же, `#pEggId`, `skip_scripts`). Только с ок владельца.
- Масштаб: ~330 серверов на libxrender-образах (java25 157, java17 126, java21 47).

## Итог QA

  Исходный баг («0», отказ) не воспроизводился: фикс уже был на проде, «до» не снималось.
