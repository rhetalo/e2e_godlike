# DEV-558 - сброс памяти сканера клиентских модов

> **В двух словах.** Запись в `server_client_only_mod_overrides` («сканер уже отключал этот хеш, если файл снова
> активен - пользователь включил сам», DEV-275) жила вечно. Uninstall → Install той же версии оставлял клиентский мод
> включённым ([DEV-492/F5](DEV-492.md#находки)). [panel!1692](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1692)
> стирает записи при явном удалении файлов. QA 21-Oct-2026 на проде: главный сценарий PASS, 1 Medium по Reinstall.

## Что изменилось
- **Uninstall мода** (`DELETE /servers/{uuid}/minecraft/mods/{provider}-{id}`, `UninstallServerModFileAction`): перед
  удалением снимает sha512 файла через ноду, после успешного удаления стирает запись только этого хеша. Не снялся хеш -
  мод удаляется, запись остаётся (старое поведение). Если кеш списка (5 мин) помнит `x.jar`, а на диске `x.jar.disabled`,
  удаляется парный файл. Uninstall удаляет файл сразу, мимо корзины.
- **Все записи сервера** (`ResetServerClientOnlyModOverrides` → `forgetAll`) стираются рядом с `ResetServerModpacksList`:
  Reinstall (`POST /reinstall`), смена версии с Wipe Server Files, установка модпака с `install_mode` `delete` или
  `backup` (`ModpackInstallMode::deletesFiles()`), удаление установленного модпака (`DELETE /minecraft/modpacks`, только
  если очистка `/mods` удалась или нода ответила 404).
- **Не сигнал сброса:** файл исчез и вернулся (файловый менеджер, корзина, SFTP), обновление пака. Ручное `.jar.disabled`
  → `.jar` и повторная заливка того же jar неотличимы. Решение зафиксировано в docblock `ResetServerClientOnlyModOverrides`.
- Миграции нет: старые записи стираются на первом же событии сброса.
