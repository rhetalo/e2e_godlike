# DEV-696 - журнал для v2 download и delete бэкапа

> **В двух словах.** До фикса скачивание и удаление бэкапа в новой панели не попадали в журнал активности сервера:
> владелец не видел, кто удалил бэкап. После panel!1792 v2 пишет те же события, что и v1. QA: PASS, prod 10-Nov-2026.
> Баг найден при QA [DEV-667](DEV-667.md) (там F1).

## Что изменилось

- `GET /api/v2/servers/{uuid}/backups/{instances|folders|databases}/{backup}/download` после выдачи ссылки пишет
  `server:backup.download` `{name}`.
- `DELETE /api/v2/servers/{uuid}/backups/{instances|folders|databases}/{backup}` после удаления пишет
  `server:backup.delete` `{name, failed}` (`failed` = бэкап был неуспешным).
- Актор - пользователь запроса (владелец, участник), субъект - сервер. У бэкапа старой панели (core, через `instances`)
  ещё субъект `backup`, как в v1. У бэкапов новой панели субъекта `backup` нет (их моделей нет в morph map).
- Пишется только после успеха: 403 (нет `backups.manage`, залоченный бэкап), 400 (чужой или выдуманный uuid), ошибка Wings - без записи.
- На free-серверах журнал не пишется вообще (общее правило `ActivityLogService`).

## Гочи для следующего раза

- Смена роли участника: `POST /api/v2/servers/{uuid}/members/change-role` `{user_id, role_id}` → 200.
- В ответе v1 `activity` поле `is_api`: запросы по токену через v1 = `true`, v2 из панели = `false`. Так v1 и v2 записи различаются.
- v1 `account` не отдаёт `uuid` - актора сверять по `email` / `username` (`include=actor`).
- Download в UI Playwright MCP скачивает весь архив (1.4 GB) в `.playwright-mcp/` - удалять.
- Лимит частоты 1 бэкап в час на instance и folder; database без окна, но общая квота слотов.
