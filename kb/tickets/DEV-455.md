# DEV-455 - Попап Free Server Gift и письма

> **В двух словах.** На страницах сайта новичку показывается попап «Получи бесплатный Minecraft-сервер».
> После регистрации или входа через попап он видит второй попап «Твой сервер готов» и за 2 клика создаёт
> бесплатный сервер, а если не создал - получает цепочку писем (Day 0/7/14/21/28). QA шёл с 24-Sep по
> 15-Oct-2026, три ре-теста. Код и письма работают, QA закрыт; остались боевые страницы показа (на авторе).

## Что изменилось
- Попап 1 (intro) «Get a Free Minecraft Server on Ryzen 6» через ~5 с на include-страницах, лимит 3 показа.
- Регистрация / вход (email, Google OAuth) из попапа → возврат на исходную страницу → попап 2 (offer).
- CTA offer → `/cart-free?productId=282` → step=2 → `POST api-cart-free.php` сразу создаёт фришку (by design).
- У кого фришка уже есть - попапов нет (`free_server_exists`), контекст очищается.
- События сценария (после 07-Oct) уходят server-side в биллинг, оттуда в eSputnik / Amplitude.
- Письма Day 0-28 шлёт eSputnik по событию `FreeServerGift`; после создания фришки цепочка должна остановиться.

## Как это работает
- Настройки: WP Theme Options → Free Server Gift (`wp_options _crb_free_gift_*_<lang>`), `campaign_id=growth95_v1`.
  JS `themes/godlike/js/free-server-gift.js`, корень `[data-free-gift-config]` рендерится только на include-страницах.
- Статус: `GET /clientarea/product_features.php?action=free_gift_status&product=282`
  (`can_start_free_flow`, `authorization_type`, `is_new_user`, `user_id` = `tblusers.id`, не client id).
- События: `POST product_features.php?action=free_gift_event` (202). Контекст: cookie `free_server_gift_ctx`
  + localStorage, `flow_id` на сценарий; возврат через cookie `free_server_gift_return`.
- Лимит 3 показа общий на вкладки, сессия = 30 мин неактивности. Попап ждёт закрытия flash-sale модалки (до 60 с).
- Free-продукты: 282 (EU), 1127 (USA). Попап всегда ведёт на 282 ❓ (вопрос открыт).
- Для автотестов: у залогиненного скрипт грузится как `rocketlazyloadscript` (после первого движения мыши).
