# DEV-637 - ошибки restore бэкапа базы

> **В двух словах.** Restore бэкапа базы раньше «проходил молча» или отдавал клиенту адрес ноды с JWT и текст MySQL с IP, а пустой
> дамп становился COMPLETED. Теперь restore читает дамп через files API панели, каждая причина сбоя - свой код и понятный текст
> en/ru/uk, фронт показывает его одним тостом, пустой дамп при создании = FAILED, битые старые бэкапы чистит `verify-dumps`.
> QA: PASS (prod 05-Nov-2026 с замечаниями, ретест доработки 09-Nov-2026 13/13, сверка чистки 10-Nov-2026).

## Что изменилось
- [panel!1749](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1749) (бэкенд, merged 04-Nov-2026) и
  [new-panel!596](https://git.godlike.ovh/panel/godlike-new-panel/-/merge_requests/596) (фронт, merged 04-Nov-2026): restore через files API
  Wings, `DatabaseBackupRestoreException` со статусом и безопасным `message`, `suppressErrorNotifications` + один тост
  (`backupCreateErrorText`, фолбэк «Failed to restore backup»), пустой дамп на create = FAILED, команда `gl:backups:databases:verify-dumps`.
- [panel!1789](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1789) (доработка по QA, merged и на проде 09-Nov-2026):
  на любую ошибку Wings сначала листинг ноды (таймаут 10 с); папка/нет файла = 409 «отсутствует»; 503 только если листинг `/` тоже упал;
  переходные состояния и suspended = `unknown` (не советуем удалять); ошибка N-го запроса дампа - отдельный текст «применён частично»;
  `verify-dumps --include-suspended`, вердикт `unreachable` не удаляется.

## Как это работает
Коды и тексты - [API - backups](../products/up/api/backups.md#post-backupsdatabasesuuidrestore-dev-637).
Дамп лежит в томе сервера: `/var/lib/pterodactyl/backups/<uuid>.sql` (`DatabaseBackupDump::path()`), виден и правится в Files -
поэтому все сценарии ошибок воспроизводятся честно, без доступа к ноде.

## Регресс
**candidate.** Контракт ошибок restore детерминирован и проверяется на проде без оплаты: на сервере с базой и одним бэкапом базы
меняем дамп через files API (`PUT files?path=`, `files/move`, `files/folder`) и проверяем коды и тексты: нет файла / папка -> 409
«missing», пробелы и 0 байт -> 409 «empty», ошибка в 1-м запросе -> 400 «could not be applied», в N-м -> 400 «applied only partially»,
рабочий дамп -> 200. Сразу не написан: это мутация (нужен `test_e2e_mut_*` сервер с базой и постоянным бэкапом базы, teardown
возвращает дамп), а создание базы в новой панели на проде однажды зависло. Предложить владельцу: спек
`tests/game/panel/backups.db-restore-errors.api.spec.ts` (serial, снимок дампа -> порча -> restore -> откат), API-only, без UI.
