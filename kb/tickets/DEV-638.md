# DEV-638 - старая панель: ссылка на того, кто качает, и журнал действий над бэкапами новой панели

> **В двух словах.** Старая панель для бэкапов новой панели (сервер, папка, база) выписывала ссылку на скачивание на
> владельца сервера, даже если качал сабюзер, а блокировка, скачивание и удаление таких бэкапов не попадали в журнал
> активности. Теперь ссылка подписана на того, кто качает, действия видны в Audit Log с автором и именем бэкапа,
> `ignored_files` больше не `[""]`. Найдено ревью [DEV-580](DEV-580.md).
> QA: PASS, prod 03-Nov-2026.

## Что изменилось
- [panel!1757](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1757) (бэкенд, master 03-Nov-2026 15:10 UTC,
  pipeline 24899). Фронт, миграции и env не менялись.
- v1 `GET /api/client/servers/{server}/backups/{backup}/download` для бэкапов новой панели: JWT подписан на `$request->user()`
  (claims `user_id`, `user_uuid`), раньше на `$server->user`.
- Там же проверка диска (`wings` / `s3`, иначе 400 «unknown disk driver type») теперь до развилки core / новая панель - для всех 4 типов.
- v1 `POST …/lock`, `GET …/download`, `DELETE …` для бэкапов новой панели пишут `server:backup.lock` / `.unlock` / `.download` /
  `.delete` (`properties.name`, у delete ещё `failed`). Subject - сервер из роута (модели бэкапов новой панели не в `enforceMorphMap`).
- `NewBackupTransformer`: `ignored_files` = `[]`, когда значения нет (у folder и database колонки нет), без deprecation в логах.
