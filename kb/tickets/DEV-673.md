# DEV-673 - кэш CORS preflight

> **В двух словах.** `config/cors.php` отдавал `max_age = 0`, и браузер слал `OPTIONS` перед каждым запросом ultra.panel
> к API (около 48% запросов панели, все через PHP-FPM; 30-Oct упёрлось в `max_children`, найдено при QA DEV-528).
> После panel!1773 ответ на preflight содержит `Access-Control-Max-Age: 7200` (env `APP_CORS_MAX_AGE`).

## Что изменилось

- `max_age` из env `APP_CORS_MAX_AGE`, дефолт 7200. Кэш выключает только явный `0` (`-1` зажимается до 0); пусто или мусор = 7200.
- `APP_CORS_ALLOWED_ORIGINS`: `trim` и отбрасывание пустых элементов.
- Касается `/api/v2/*` и `/api/client/*` (`cors.paths`). Фронт и nginx не менялись.

## QA (prod, 11-12 Nov 2026)

Итог: **PASS**, все шаги MR и DoD закрыты (шаги 6-7 через тесты MR). Страница API: [UP/api/cors](../products/up/api/cors.md).


- curl OPTIONS: `/api/v2/*` и `/api/client/*` дают 204 и одну строку `access-control-max-age: 7200`; `/auth/login` без заголовка; чужой origin без ACAO и Max-Age; PUT/POST/DELETE тоже 7200.
- Chrome (Playwright MCP + CDP `Network.requestWillBeSent`, т.к. Playwright сам preflight не показывает): первый заход на сервер 25 OPTIONS / 67, перезагрузка 0 / 44; папки в Files: OPTIONS только на первый заход.
- Шаги 6-7 (откат на stage) не делали: нужна правка `.env`, покрыто `CorsConfigTest` / `CorsPreflightTest` в MR.
- ✅ DoD 3 (DevOps, 12-Nov, nginx `signoz-access.json`): доля OPTIONS 47.5% (база 05-09.11, логи 30.10-04.11 уже ротированы) → 34.4% 10.11 (день деплоя) → **9.4% 11.11**, 9.1% 12.11. OPTIONS около 3 млн → 305 тыс. в сутки (-90%), остальные запросы без изменений (около 3 млн в сутки). Оставшиеся 9% - первый запрос на новый URL и повтор после 2 ч.

## Гочи для тестов

- Playwright `page.on('request')` и MCP `network_requests` CORS preflight НЕ видят. Нужен CDP: `context.newCDPSession(page)` + `Network.enable`, preflight приходит как `method: OPTIONS`.
- Кэш preflight per URL с query; сервер сбросить его не может (до 2 ч).

## Регресс

`covered`: [tests/game/panel/cors.preflight.api.spec.ts](../../tests/game/panel/cors.preflight.api.spec.ts) (12-Nov-2026, burn-in 5x зелёный). Read-only OPTIONS без авторизации: `/api/v2/servers/{uuid}` и `/api/client/servers/{id}` от ultra.panel дают 204, свой `allow-origin` и **один** `access-control-max-age` > 0 (значение не пиним, оно в env); чужой origin без CORS-заголовков. Браузерное поведение (кэш, отсутствие OPTIONS при повторе) в e2e не идёт: Playwright не видит preflight без CDP, а контракт заголовка его и так гарантирует.
