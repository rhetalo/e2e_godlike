# DEV-500 - Скрытие чисто клиентских модов в каталоге

> **В двух словах.** Есть моды, которые нужны только игроку (шейдеры, миникарты, твики интерфейса). На сервере они
> бесполезны или роняют его. Теперь каталог модов в панели их не показывает, а моды, нужные и клиенту, и серверу,
> остаются. QA закрыто 12-Oct-2026: PASS, остались мелкие неточности из-за разметки самих CurseForge-модов.

## Что изменилось
- Modrinth: скрываются моды с `server_side=unsupported` (+ пост-фильтр live-выдачи).
- CurseForge: решение по меткам `Client` / `Server` в `gameVersions` **самого нового файла под выбранные loader + version**
  (panel!1672). Мод скрыт, если есть хотя бы одна метка Client и ни одной Server; файл без меток - откат на `latestFiles`.
- Пустая страница каталога: «Nothing found / Nothing matches the current filters», без Total и без «Try the next page»
  на последней или единственной странице (new-panel!547).
- В конструкторе модпаков клиентские моды остаются специально.
- Прямой `POST /minecraft/mods {provider, mod_id, version_id}` скрытый мод всё равно ставит (скрытие только в каталоге).

## Как это работает
- Данные Modrinth о среде: таблица `mods` (panel DB) + live search API Modrinth. У CurseForge в БД поля среды NULL (10003 записи).
- Индекс Modrinth матчит проект по среде, если хоть одна версия client_and_server/unknown - отсюда редкие утечки (JEBr, FISM).
- Гоча стенда: на сервере 26.x пустой loader = loader и версия сервера, а под 26.3 модов почти нет. Для выборок
  фильтры ставились вручную (Forge 1.20.1, Fabric 1.21.1).
- Скорость: CF страницы 2-4 стали 370-530 мс (было 240-520), Modrinth без изменений (~250 мс).
