# DEV-593 - квиз апгрейда работает только с токеном владельца

> **В двух словах.** JSON API квиза апгрейда в биллинге (аддон `upsell_quiz`) не проверял, кто спрашивает: проверки владельца были
> закомментированы при переносе квиза в панель. Зная чужой `service_id` (идут подряд), можно было пройти квиз за чужую услугу,
> подменить продукт в оффере и принять апгрейд со списанием с карты владельца. Теперь панель выдаёт владельцу сервера подписанный
> токен на 1 час, биллинг без него отвечает 401, на ресурс другой услуги 403. Квиз живёт только в новой панели.
> QA: PASS, prod 30-Oct-2026, с реальным апгрейдом за кредиты и атаками на все эндпоинты.

## Что изменилось
- [billing!762](https://git.godlike.ovh/billing/billing-godlike-host/-/merge_requests/762): проверка токена и владельца в `ClientDispatcher`
  до контроллера, CORS для панелей, отказы сначала только логировались. [billing!764](https://git.godlike.ovh/billing/billing-godlike-host/-/merge_requests/764):
  отказы блокируют запрос, CORS квиза без `Allow-Credentials`.
- [panel!1729](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1729): выдача токена владельцу
  (`GET /api/v2/servers/{uuid}/upgrade-quiz/token`). [panel!1731](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1731):
  квиз убран из старой панели, кнопка «Go to quiz» ведёт в новую; старый маршрут токена `api/client/...` удалён (404).
- [new-panel!588](https://git.godlike.ovh/panel/godlike-new-panel/-/merge_requests/588): фронт шлёт токен в каждом запросе к биллингу,
  на 401 один раз берёт новый токен и повторяет запрос, экраны «unavailable» и «Session expired».
- Закрыты все эндпоинты: `quiz/show`, `submission/*`, `offer/index|store|update|destroy`, `pricing/show`, `upgrade/store`.
