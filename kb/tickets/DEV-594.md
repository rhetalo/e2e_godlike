# DEV-594 - RAM модпака округляется до реального плана

> **В двух словах.** Диалог «модпаку не хватает RAM» вёл на страницу апгрейда с `?ram=5` (5000 MB / 1000 вниз), а такого
> плана нет - страница открывалась без Recommended. Теперь любое `?ram=N` сводится к наименьшему плану `>= N` из реальной
> сетки тарифов (выше сетки - максимальный), диалог считает GB с округлением вверх, кнопка - «Upgrade RAM» без размера.
> QA: PASS, prod 02-Nov-2026, без покупок (цена сверялась до оплаты).

## Что изменилось
- [new-panel!576](https://git.godlike.ovh/panel/godlike-new-panel/-/merge_requests/576) (смержен 29-Oct-2026), только фронт:
  - `snapRamToPlan(products, ram, currentSlots)` в `upgradeTariffs.ts`: наименьшая ступень `>= ram` из `buildRamOptions`
    (ступени `>= currentSlots`); выше сетки - максимальная; нет запроса или ступень `<=` текущей RAM платного сервера - `null`
    (без Recommended). `useUpgradePage.ramQuery` теперь уже округлённое значение.
  - `mbToGbCeil` - `Math.ceil` вместо деления вниз.
  - `ExtensionInstallDialogs.vue`: `recommendedRamMb = best_ram || 4096`, «Most players use N GB+», кнопка
    `Server_Extensions.Modpack.UpgradeRam` (fallback «Upgrade RAM»), ссылка `?ram=mbToGbCeil(recommendedRamMb)`.

## Как это работает
- **Сетка на проде (02-Nov):** 2, 4, 6, 8, 10, 12, 14, 16, 20, 32, 64, 96, 130 GB - шаг 2 GB до 16, не 1 GB, как в тикете (N-1).
- **Когда показывается RAM-диалог** (`useServerExtensions`): `requiredRam = max(best_ram || 4096, 4096)`; диалог только если
  `requiredRam > limits.memory`. Иначе **Install сразу ставит модпак** (затирает сервер).
- `best_ram` берётся из ответа API списка модпаков (`ram_requirements.amount_mb`, у FTB live `estimated_mb`), а не из колонки
  `modpacks.ram` в panel-БД. Слот выбирается по maxPlayers из `/players`; у offline-сервера 0 → фронт берёт 4 (слот [3,4]).

Подробно - [UP/upgrade](../products/up/upgrade.md), [UP/modpack-catalog](../products/up/modpack-catalog.md).
