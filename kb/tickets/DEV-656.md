# DEV-656 - окно подтверждения апгрейда закрывается после оплаты

> **В двух словах.** С коммита `43b54a2c` (09-Aug) оплаченный апгрейд оставляет клиента в панели, но окно
> «Confirmation Of Tariff Plan Change» после `paid` не закрывалось: через пару секунд в нём был «Quadra → Quadra»
> с активным Confirm, клиент мог заплатить второй раз. Теперь окно держит старый → новый план и заблокированные
> кнопки до исхода, на `paid` закрывается, страница показывает новый план. QA: PASS, prod 10-Nov-2026, 5 реальных покупок.

## Что изменилось
- [new-panel!610](https://git.godlike.ovh/panel/godlike-new-panel/-/merge_requests/610) (o.voloshyn), только FE, выкатка pipeline 25310 (10-Nov ~14:50):
  - `useUpgradeSettlement.settleUpgrade` async: на `paid` тост и ожидание рефетча `GET_CURRENT_TARIFF`, `GET_TARIFFS_LIST`, `GET_SERVER_BY_ID`
    (до 10 с); сбой или таймаут → `window.location.reload()`. Троттлинг зовёт с `reloadWhenStale: false`.
  - Общий `useUpgradeSuccessCallback` для конфигуратора (`useSimplePlanCard`) и сетки See All Plans (`PlanCard.vue`):
    loading до исхода (окно persistent, Confirm / Cancel / крестик заблокированы), на `paid` сначала закрытие окна и `upgraded`, на `redirect` loading не снимается.
  - Страница `/server/{id}/upgrade` на `upgraded`: закрывает окно, сбрасывает `selectedPlanState`, перемонтирует карточки (`upgradeRefreshKey`).
  - `UpgradePlanConfirmationDialog` показывает снимок «текущий → выбранный», пока идёт оплата и окно закрывается.
- Баг был на обеих поверхностях страницы, не только в `PlanCard.vue`, как предполагал тикет.

## Гочи
- Нативный путь (`GodlikeUpgrade native svc ...`) при нехватке кредита: WHMCS **сам частично** применяет кредит при создании счёта
  («Credit Automatically Applied at Invoice Creation», Local API User), остаток - к оплате (338268: €2.71 − €1.04). На ручном пути
  ([DEV-657](DEV-657.md)) панель при нехватке кредит не трогает.
- Нативный путь без промо - c8e6dbed; b1b0b2ed даёт промо-цену (перечёркнутая) = ручной путь.
- Free-сервер получает скидку на первый апгрейд (Quadra €12.99 → €3.25, `is_discounted: true`).
- Мок `pay` через `page.route` не спасает от записи: `POST /upgrades` уже создал intent, он остаётся `pending` без счёта до `expires_at` (+15 мин).
- Признаки исхода в `upgrade_intents`: `paid` + `invoice_id`; редирект = `failed` + «Payment Attempt Failed» + `invoice_id`.
- `redtrack.godlike.host/clickupd` отвечает 409 на каждой загрузке страницы - трекер, не апгрейд.

## Регресс
**no**: каждый шаг = настоящая оплата апгрейда кредитом на проде (деньги с баланса, смена тарифа). Мок 429 тоже не read-only:
`POST /upgrades` создаёт intent. Закрытие окна видно только после реального `paid`.
Если появится stage с WHMCS-песочницей - покрыть «paid → окно закрыто, в карточке Nothing To Save» на обеих поверхностях и «429 → окно открыто, кнопки активны».
