# DEV-547 - апгрейд с Premium-сервера остаётся в Premium

> **В двух словах.** Premium-серверу на странице апгрейда предлагали Budget: в See All Plans у карточек по умолчанию стояла
> вкладка Budget, `?ram=` / модпак подбирали план по RAM без тира, квиз отдавал Budget-план. Теперь правило одно: тир
> предложенного и предвыбранного плана = тир текущего сервера; переключатель Budget / Premium остаётся. Плюс аналитика тира:
> новые поля событий страницы, вход из клиентской зоны WHMCS, план «до» в событии оплаты `upgrade`.
> QA: PASS, prod 04-Nov-2026.

## Что изменилось
- [new-panel!568](https://git.godlike.ovh/panel/godlike-new-panel/-/merge_requests/568) (29-Oct): тир сервера по линейке тарифов
  (для плана вне линеек - `attributes.isPremium`); сетка See All Plans стартует в тире сервера, при смене тира карточка берёт pid
  и группы опций выбранного тира; выбранный тир переживает переход сетка ↔ конфигуратор (`useUpgradeChosenPlanType`), сбрасывается
  reload, уходом со страницы, новым Boost и сменой сервера. События: opened `chosen_plan_type`; changed `surface`,
  `current_plan_type`, `pid_after`, `plan_after`; toggled `current_plan_type`. Метки входа `client_area` (снимается с URL),
  `premium_benefits`, Back квиза = `upgrade_quiz`. Квиз: Premium-серверу заголовок «Upgrade your plan for better performance!».
- [panel!1699](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1699) (29-Oct): приём и валидация новых полей
  (422 + warning `upgrade_page_event.rejected`), `UpgradeFlowName::premium_benefits`, ссылка письма Lag Score с `ram=<recommended_ram_gb>`.
- [billing!740](https://git.godlike.ovh/billing/billing-godlike-host/-/merge_requests/740) (04-Nov): квиз заменяет Budget-план
  Premium-парой для Premium-сервера; событие `upgrade` получает `items[0].previous_pid/previous_plan/previous_plan_type` и
  `item_variant`; «Upgrade/Downgrade» в клиентской зоне ведёт на панель с `?entry=client_area`.

## Как это работает
- Тир = наличие продукта в `godlike_budget_premium_pair` (billing). Платный план вне пар - `budget` (и в событии оплаты).
- Id опций у тиров MC общие (группа 104 CPU, значение 751 «Default» и т.д.): «Default» = 3 vCores / 30 GB у Budget и Max / 200 GB
  у Premium. Одинаковый `config_options` в calc обоих тиров - норма.
- Payload события `upgrade` виден в `tblactivitylog`: `description LIKE 'upgrade data:%'`; отправка кроном через ~1-3 мин после
  оплаты, дедуп `godlike_analytics_event_dedupe` (`upgrade.native.<tblupgrades.id>`, `upgrade.new.<invoice>`). Апгрейды из
  админки WHMCS событие не шлют.

Подробно - [UP/upgrade](../products/up/upgrade.md).

## Гочи
- В сетке See All Plans, пока догружаются calc, кнопки «Save Setup» меняются: селектор «первая Save Setup» попадает в соседнюю
  карточку. Кликать по карточке через её заголовок `h3`.
- Модпак-диалог на Premium 4 GB: офлайн-сервер берёт слот [3,4] → 6144 MB → диалог есть. POST `minecraft/modpacks` в пробе
  блокировать через `page.route`, иначе Install поставит модпак.
- Под админ-видом на чужом сервере расчёт апгрейда 404 - так задумано ([BUG-max-plan-tier-pairs](../products/up/upgrade.md)).
