# DEV-633 - Wings отдаёт 404 вместо 500 на несуществующий файл

> **В двух словах.** Запрос содержимого или скачивания файла, которого нет, падал в Wings с 500. Внешний клиент
> (`HoloControl/1.0`) дёргал такие файлы по кругу: ложные алерты Zabbix «Nginx 500» на app.panel и ~13 тыс. строк в
> Graylog в сутки. Фикс в Wings: теперь 404 «The requested resources was not found on the system». QA на stage 09-Nov-2026 -
> PASS; на прод фикс ещё не выкачен (Jira «Waiting for Release»).

## Что изменилось

- `GET /api/client/servers/{id}/files/contents?file=<нет такого>`: 500 → **404** с текстом Wings.
- То же для «файл как папка» (`server.properties/***`), файла в несуществующей папке, `../` и имён с кириллицей / пробелом / `%`.
- Скачивание: панель по-прежнему выдаёт signed URL без проверки файла, а сама ссылка на Wings теперь отдаёт 404, не 500.
- Существующие файлы: 200; файл больше `max_edit_size` - 400 `FileSizeTooLargeException` (как и раньше).
- API новой панели (`/api/v2/.../files/contents?path=`) заворачивает ответ Wings в **400** с тем же текстом - 500 нет.

## Как это работает

- Новая панель на несуществующий файл **запрос не шлёт**: сверяется с уже загруженным списком и сразу показывает тост
  «Unable to open file». Поэтому фикс через адресную строку виден только в старой панели (F12 → Network) и через API.
- Подробности кодов - [API files](../products/up/api/files.md#ошибки-файлов-dev-633).
