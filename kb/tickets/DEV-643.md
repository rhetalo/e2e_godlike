# DEV-643 - один маппинг PUT бэкапа и scope «бэкапы сервера»

> **В двух словах.** Рефакторинг без изменения поведения. Правило «какие поля PUT пишутся в бэкап» было скопировано в три
> Update-action (сервер, папка, база), условие «бэкапы этого сервера» - в 16 мест в 6 репозиториях. Теперь и то, и другое
> в одном месте, расхождение копий больше невозможно. QA: PASS, prod 04-Nov-2026, регресс всех трёх типов бэкапов новой панели
> и бэкапа старой панели. Попутно найден баг прода [DEV-677](https://antihost.atlassian.net/browse/DEV-677) (phpMyAdmin и импорт SQL).

## Что изменилось

- Маппинг PUT: трейт `MapsBackupUpdateColumns::toColumns()` на трёх Update DTO, actions вызывают его одной строкой 📖. Пишется только
  переданное поле (`null` = не пришло, `false` и `0` пишутся); `schedule_date` / `schedule_time` - только вместе с `schedule: true`
  ([DEV-585](https://antihost.atlassian.net/browse/DEV-585)); у папки дополнительно `path`, `ignoredFiles` не мапится (колонки нет).
- Scope `forServer(int $serverId)` на `BackupInstance`, `BackupFolder`, `Backup` (старая панель) - `server_id`; на `BackupDatabase` -
  через `whereHas('database')` 📖. Заменил копии в Instance/Folder/Database/Backup/BackupQuota репозиториях и upstream
  `Pterodactyl\Repositories\Eloquent\BackupRepository`: список, поиск по uuid ([DEV-580](DEV-580.md)), «бэкап уже идёт», квота слотов и окно частоты.
- Тесты MR: поля расписания в PUT по 3 типам, юнит `toColumns()`, scope на 4 моделях 📖.

## Регресс
**candidate.** Матрица PUT по трём типам детерминирована и идёт на проде без оплаты: PUT каждого поля, PUT одного поля не сбрасывает остальные,
гейт даты (422 на прошедший разовый запуск). Это закрывает гэп «Rename, Lock, Database / Folder, создание расписания - не покрыто» в
[UP/backups](../products/up/backups.md#покрытие). Сразу не написан: PUT - мутация, нужен бэкап каждого типа на mut-сервере
(`test_e2e_mut_*`) с откатом в teardown, а создание бэкапов там упирается в общее окно частоты (1/ч), на котором держится
`backups.throttle.spec.ts` (fd965a60). Предложить владельцу: отдельный mut-сервер с постоянными instance/folder/database бэкапами
и спек `backups.update-fields.api.spec.ts` (serial, снимок → PUT → откат).
