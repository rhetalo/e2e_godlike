# DEV-529 - Arclight после старта: тип ядра больше не перезаписывается

> **В двух словах.** Arclight - гибрид, который запускает и моды, и плагины. После запуска сервера панель видела
> внутри него Forge или NeoForge и начинала показывать сервер как Forge/NeoForge, путала версию Java и подборку модов.
> Теперь тип остаётся Arclight, а моды подбираются под его вариант (forge / neoforge / fabric). QA закрыто 08-Oct-2026: PASS.

## Что изменилось
- Arclight forge / neoforge / fabric после Start, Restart и «Refresh version» остаются `ARCLIGHT` с выбранным билдом.
- `required_java` и `latest` считаются по Arclight той же flavor (Arclight 1.20.1 `max:null`).
- Start не ставит чистый loader поверх гибрида: Arclight + моды + плагины грузятся (`Launching target 'arclightserver'`).
- Flavor используется в: `extension_capabilities.mod_loader`, missing-mods (`resolve-missing` `meta.loader`), optimization-mod
  (`godlikemetrics` кладётся по flavor).
- Mohist: после Start/Restart/Refresh установленный билд сохраняется (был `build:null`) - фикс 08-Oct.

## Как это работает
- Источник проблемы (DEV-506/F1): `/minecraft/versions/installed` определял билд по файлам и видел библиотеки
  `libraries/net/minecraftforge/forge/...` / `neoforged/neoforge/...` внутри Arclight, затем перезаписывался `/minecraft/version`.
- Скоуп фикса (согласован владельцем с разработчиком): детект после старта, проверка ядра на Start, flavor для
  mods / capabilities / missing-mods / latest, optimization-mod по flavor, Mohist/Youer/Magma «если можно». Уже испорченные серверы не чинятся.
- Youer и Magma в каталоге панели нет.
