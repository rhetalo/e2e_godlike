# DEV-661 - Rollback и блокировка переноса в Wings

> **В двух словах.** После переноса Wings старой ноды держал оставленную копию сервера с флагом «в переносе».
> Сервер, вернувшийся туда (Rollback или A→B→A), не стартовал: «server is currently being transferred», лечилось только
> рестартом Wings. Плюс ошибка любого шага Rollback давала 500 и обрывала остальные шаги. Фикс в двух частях:
> Wings снимает блокировку по sync / входящему переносу, панель при Rollback шлёт sync на ноду возврата и не
> обрывает шаги при ошибке. QA закрыт 09-Nov-2026 на stage, все 6 кейсов PASS.
> Наш клон-баг с тем же симптомом - [DEV-688](https://antihost.atlassian.net/browse/DEV-688) (найден в [DEV-659](DEV-659.md)).

## Что изменилось

- [panel!1768](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1768) (master 04-Nov-2026, stage 09-Nov-2026 `e3341544`):
  - `ServerTransferRollbackController::store`: catch-блоки читали `$server->transfer->id` (связь всегда `null` при откате) и
    сами падали - теперь пишут id записи отката, остальные шаги (порты, БД, DNS поддомена, NetherNet) выполняются;
  - отдельный шаг: `sync` сервера на ноде, куда его вернули (после обновления портовых переменных), ошибка только логируется;
  - тест `ServerTransferRollbackTest`.
- [wing-panel!14](https://git.godlike.ovh/panel/wing-panel-godlike-host/-/merge_requests/14) (Wings, репо токену QA недоступно):
  снимает блокировку копии по sync и при входящем переносе; sync для сервера, которого нет на ноде, → 404.
- Порядок деплоя по MR: сначала Wings, потом панель.
