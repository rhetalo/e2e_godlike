# DEV-587 - письма через notifications-center выключены

> **В двух словах.** После Reinstall, Restore и ещё 5 действий панель слала письмо через `notifications-center`, мёртвый
> около года. Обычно сервис сразу отдаёт 502 и панель это глотает, но когда он висел, первый вызов
> (`fetch-ids-by-emails`, без таймаута и без try/catch) ждал 30 с и ронял запрос в 400, а шаги после письма терялись
> (21-Oct-2026 ~14:27-15:00 UTC). [panel!1806](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1806)
> выключил отправку флагом, перенёс сбросы Reinstall до письма и убрал адреса из лога. Prod PASS 11-Nov-2026.
> Тикет заведён QA (владелец).

## Что изменилось

- Флаг `NOTIFICATION_SENDING_ENABLED` (`config/notification.php` → `sending_enabled`), по умолчанию `false`.
  `NotificationService::notify()` при выключенном флаге сразу выходит. Удалять вызовы не стали: вернуть сервис = одна строка в env.
- Через `notify()` идут все места отправки: `ServerReinstallController`, `RestoreBackupInstanceService`,
  `RestoreBackupFolderService`, `RunTaskAction` (только задачи с `time_offset`), `UpdateServerGameVersionAction`,
  `ServerMinecraftModpackController`, `JavaStartGateAction::notifyByNotificationCentre`. Письмо гейта Java через Laravel Mail
  (`notifyByMail`) не затронуто.
- `ServerReinstallController`: `ResetServerModpacksList` и `ResetServerClientOnlyModOverrides` (только `reallocate`) теперь до `notify()`.
- `NotificationCenterUserService::findByEmails`: в лог `emails_count` вместо списка адресов.
- Чтение (колокольчик, `NotificationController`) не тронуто.
- 136 тестов, в том числе Reinstall 200 и сбросы при висящем сервисе, оба Restore, флаг по умолчанию выкл.

## Гочи

- `RunTaskAction` шлёт письмо только для задачи с `time_offset`; проверка без отправки команды - `POST /tasks/run` на offline-сервере.
- `POST /servers/{uuid}/version` требует в теле `server_id` (полный uuid), иначе 400 TypeError из `HasServer` ещё до валидации.
- Reinstall с Delete files на MC-сервере сначала показывает окно World Backup («Continue Without Backup»), запрос уходит только после него.
- Во время Reinstall с Delete files `GET files?dir=/mods` отдаёт 400 (папки нет) - шум, не баг.
