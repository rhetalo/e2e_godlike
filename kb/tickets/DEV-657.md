# DEV-657 - апгрейд ручным путём теперь гасится кредитом

> **В двух словах.** Когда биллинг не может провести апгрейд сам (промокод, доплата CPU), панель выставляет счёт
> сама. Раньше она звала `ApplyCredit` без суммы, WHMCS ничего не применял, клиента без карты уводило на счёт,
> intent оставался `failed`. Теперь, если кредита хватает на весь остаток, панель гасит счёт кредитом сама, апгрейд
> применяется, клиент остаётся в панели. QA: PASS, prod 10-Nov-2026, включая две настоящие покупки за кредит.

## Что изменилось
- [panel!1779](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1779) (s.itskovich, ревью o.voloshyn, merged 09-Nov 08:36 UTC),
  `app/Services/Tariff/InvoiceCaptureAction::handle`:
  - `GetInvoice` → если Unpaid: `balance` счёта + `credit` клиента (`GetClientsDetails`).
  - credit >= balance → `ApplyCredit(invoiceid, amount = balance)`, статус перечитывается.
  - credit < balance → ApplyCredit **не** отправляется, остаток целиком в `CapturePayment`, кредит остаётся на балансе.
    Частичное применение убрано по ревью: при неудачном capture кредит застревал бы на брошенном счёте.
  - Нет `userid` / `balance` или клиент не прочитался → `Log::warning`, без ApplyCredit. Отказ ApplyCredit → warning, дальше capture.
- Описание MR ещё говорит про частичное применение - устарело, финальный код его не делает.
- Тот же код у legacy-панели (`source=panel_v1`) и у доплаты CPU - один `InvoiceCaptureAction`.
