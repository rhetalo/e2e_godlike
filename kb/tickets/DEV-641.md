# DEV-641 - world-бэкап ищется только в рамках своего сервера

> **В двух словах.** Доделка [DEV-580](DEV-580.md) для World Backups (находка F4 из финального ревью DEV-580). Retry, restore и destroy
> искали world-бэкап по uuid во всей таблице и только потом сверяли сервер. Чужой uuid отвечал «does not belong to this server»,
> выдуманный - «No query results», так что по ответу было видно, существует ли чужой uuid (оракул; IDOR не было). Теперь поиск идёт
> сразу по серверу и uuid, чужой и выдуманный uuid отвечают одинаково. QA: PASS, prod 03-Nov-2026.

## Что изменилось
- [panel!1750](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1750) (бэкенд, влит в master 03-Nov-2026 11:34 UTC). Фронт не менялся,
  миграций и env нет.
- `WorldBackupController` retry / restore / destroy: `getWorldBackupByUuid` → `getWorldBackupByServerIdAndUuid($server->id, $uuid)`.
  Inline-сравнение `server_id` из контроллера и `assertBelongsToServer` из `RetryWorldBackupService` убраны.
- В `WorldBackupRepositoryContract` добавлены `getWorldBackup[OrNull]ByServerIdAndUuid` по образцу DEV-580.
- Коды: restore и destroy с чужим uuid были 404, стали 400 (как все v2-эндпоинты бэкапов после DEV-580). Retry был 400 и остался.
- `getWorldBackupByUuid()` остался без вызывающих, удаление вне задачи 📖.

## Итог QA

сервера B2 [srv:546bc52e](../registry/test-servers.md#546bc52e); второй аккаунт - сервер `test_e2e` ebb03adc (test@testmail.com).

гонять на проде без риска.
