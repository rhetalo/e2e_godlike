# DEV-678 - кто ставит моды руками по SFTP

> **В двух словах.** Новый детект не писали. Wings и раньше пишет каждую SFTP-запись в `activity_logs`
> (`server:sftp.create/write/rename`), а MR добавил страницу `/admin/sftp-mod-uploads`: список клиентов,
> загружавших `.jar` прямо в `mods/`, с разворотом по серверам и файлам. QA: PASS, prod 10-Nov-2026, живая
> SFTP-загрузка на DEV-559-forge (1d7d34aa) дала ровно 4 ожидаемых файла.

## Как работает
- [panel!1791](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1791):
  `SftpModUploadController` → `SftpModUploadReportService` → `SftpModUploadRepository`. Меню админки: «SFTP Mod Uploads».
- Источник: только `server:sftp.create|write|rename` с `actor_type=user`. Другие пути пишут свои события, отчёт их не читает:
  веб-менеджер → `server:file.upload` / `server:file.uploaded`, вкладка Mods → `server:mod.install`, модпак → `server:modpack.install`.
- Паттерн: `~(^|/)mods/[^/]+\.jar$~`. Не считаются `mods/sub/x.jar`, `plugins/`, корень, `.jar.disabled`, временные
  `.filepart/.staged/.pending/.uploading`. Для rename считается только `to`.
- Единица: уникальный путь jar на (клиент, сервер, календарный день UTC). Клиент = actor SFTP-сессии, не владелец.
- Период → диапазон id бинпоиском по PK (индекса по `timestamp` нет) ± 6 ч, потом точный фильтр по `timestamp`.
  Предфильтр `LIKE '%mods%.jar%'` без слэша (MariaDB хранит `\/`).
- Фильтры: `from`/`to` (Y-m-d, по умолчанию 30 дней), `search` (email, username, имя сервера, UUID-префикс, id, external_id), 25 на страницу.
- Лог хранится 90 дней (`activity.prune_days`). Страница открыта любому админу.

## Находки
- **OBS-1** 90 дней = 11.5 с (30 дней = 2.6-2.9 с). Не блокер.
- **OBS-2** Время в UTC без подписи зоны (15:49 Киев → «1:49 PM»).
