# DEV-512 - Смена версии теряет libxrender

> **В двух словах.** Если сервер стоял на «Java 17 libxrender» и клиент менял версию Minecraft, панель
> ставила обычную «Java 21», и моды, которым нужна libxrender, переставали работать. Теперь суффикс
> сохраняется: «Java 17 libxrender» превращается в «Java 21 libxrender», а обычный сервер остаётся на
> обычной Java. Заведено QA по итогам [DEV-486](DEV-486.md), закрыто 02-Oct-2026, добито 07-Oct. PASS.

## Что изменилось
- `JavaImageMatcher::pick()` получил текущий образ сервера: если он `-libxrender` и в egg есть libxrender-вариант
  нужной Java, берётся он; иначе поведение как раньше (первый по порядку в egg).
- Правка во всех 4 местах выбора образа: легаси changer, новый changer, установка ядра (`applyJavaImage`),
  `ApplyRequiredJavaImageAction`. То есть касается и старой, и новой панели.
- Клиенты без libxrender изменений не замечают.

## Как это работает
- Причина (Jira): `pick()` не видел текущий образ, внутри major побеждал первый в `docker_images` egg.
  В egg 121 порядок асимметричный: для 17 и 25 первым стоит libxrender, для 21 - plain.
  Поэтому апгрейд 17 → 21 молча терял libxrender, а апгрейд в 17 plain-серверу ставил libxrender.
- Масштаб: ~330 серверов на libxrender-образах.

## Итог QA
- 02-Oct-2026: закрыт ✅ (C8b в матрице: Fabric 1.20.5 → образ `java21-libxrender`). Отдельного отчёта нет ❓.
- 06-Oct обратная сторона: changer ставил libxrender plain-серверам на Java 17 ([DEV-472](DEV-472.md)/R1).
- 07-Oct после [panel!1655](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1655): plain Java 8 → Forge 1.20.1 = plain Java 17 ✅;
  «Java 17 (libxrender)» → Fabric 1.21.1 = «Java 21 (libxrender)» ✅; plain Java 21 → Fabric 1.20.5 = без изменений ✅.
- 12-Oct попутно в старой панели (в рамках [DEV-513](DEV-513.md)): `java17-libxrender` → `java21-libxrender` ✅.
- По демо 08-Oct: DEV-512 проверялся в новой панели; в старой отдельно только DEV-486 (до 12-Oct).
