# DEV-472 - Автодетект Java и попап ошибки

> **В двух словах.** Каждой версии Minecraft нужна своя Java. Панель должна сама понимать, какая Java
> нужна серверу, и если сервер упал из-за неподходящей Java - показать окно «нужна Java N» с правильным
> вариантом. QA со 02-Oct по 08-Oct-2026 нашёл 9 проблем (ложные попапы, неверная Java после модпака),
> разраб исправил, все шаги MR закрыты кроме лаунчера. PASS.

## Что изменилось
- Требование к Java (`required_java`) считается из колонок версии (`columns`) или из каталога модпака
  (`modpack_catalog`), источник свежее выигрывает (миграция `2026_10_02 add_minecraft_core_changed_at`).
- «Слишком новая» Java больше не открывает попап; вердикт привязан к образу и запуску.
- В попапе предвыбрана рекомендованная Java (plain-образ, не libxrender), запись по Save, Close ничего не меняет.
- После установки модпака панель обновляет версию MC / лоадер, установщик ставит подходящую Java.
- Рестарт из попапа ждёт power-lock вместо ошибки «another power action».
- Changer сохраняет libxrender только тем, кто на нём был (связано с [DEV-512](DEV-512.md)).

## Как это работает
- Попап (старый механизм, флаг [flag:java-mismatch-fixer](../registry/flags.md#java-mismatch-fixer), вкл. глобально)
  реактивный: фронт парсит лог краша → `POST minecraft/java-error` → «Java Version Error».
  Показывается только у того, у кого открыта вкладка, и только при фронтовом Start.
- `GET .../minecraft/server-jar/status` отдаёт `java_preflight {verdict, recommended, min, max}`; после фикса
  заполняется только при `too_old`.
- Запись модпака в `server_modpacks` переживает Wipe и смену версии; снимается Uninstall или вайпом с 26.x.
- Тоггл автодетекта: клиентский Config «Enable Auto-detect Loader & Version» (`minecraft_autodetect_enabled`).
- Цепочка модалок при установке пака: needs more RAM → Install Anyway → Save Your World First? → Continue Without Backup → Some mods were disabled.
