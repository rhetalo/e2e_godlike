# DEV-670 - Seed finder: кэш и каталог JSON

> **В двух словах.** На каждый запрос `/minecraft-seeds/` WordPress заново собирал данные всех сидов (~15 тыс. SQL)
> и вшивал весь каталог (~800 КБ JSON) в HTML: TTFB 8 с, CrUX LCP 8 с. После wp!831 данные лежат в transient,
> в HTML только первый экран, каталог грузится отдельным запросом. TTFB 0,56-0,70 с, HTML 192 КБ.

## Что изменилось

- `new-seed-calculator/bootstrap.php`: данные finder в transient `godlike_seed_finder_<код>_<поколение>` (`wp_options`, `autoload = no`, ~784 КБ),
  TTL 12 ч (первые 5 мин после деплоя - 5 мин). Сброс на `shutdown` при изменении опубликованного сида, его мета, связей `seed_filter`,
  термов фильтров, удалении вложения. Поколение - опция `godlike_seed_finder_generation`.
- `window.GodlikeNewSeedCalculator`: опции версий и фильтров, `initial` (версия по умолчанию, `total`, 3 карточки), `catalogUrl`. Массива `seeds` нет.
- `GET /wp-json/godlike/v1/seed-finder?v=<версия>` → `{version, seeds}`. С актуальной `v` - `public, max-age=43200`; без `v` или со старой - `no-store`; `POST` → 404.
  Поля `id`, `excerpt`, `modpackVersionId/Name` убраны.
- JS/CSS переименованы `seed-calculator.*` → `seed-finder.*` (минификация WP Rocket кэширует по пути). Корень получает `data-sc-catalog="loading|ready|error"`.
- На шаблоне лендинга фильтр `rocket_delay_js_exclusions` исключает все скрипты, но runtime Delay JS остался в HTML (см. F1).

## QA (prod, 13-Nov-2026)

Итог: **PASS**, все 13 шагов MR закрыты.

- TTFB `/minecraft-seeds/` 7,6-8,4 → 0,56-0,70 с, `/page/2/` 8,0 → 0,69 с; HTML 990 → 192 КБ; DOMContentLoaded 10,1 → 1,1 с.
- Счётчики finder сходятся с JSON-каталогом: 1.18 = 78, 1.19 = 939, 26.1 = 962, ATM10 v6.2.1 = 17, v6.1 = 15 (модпак по `modpackId` = `composite`), Java/Bedrock, теги.
- Без действий посетителя: `ready` за 1,5 с, cookie `utm_*`, `godlike_referrer`, `pll_language` пишутся, hero не прыгает.
- Негатив (route в своём браузере): блок каталога → первый экран тихо, по действию «Couldn't load the seed list.» + «Try again»; задержка 5 с → «Loading seeds…»; битый JSON → `error`.
- Шаг 12 по БД: `_transient_timeout_godlike_seed_finder_*` = пересборка + 12 ч, старая запись удалена. Шаг 13 пойман вживую: публикация сида 11:56:50 UTC → одна холодная загрузка 8,9 с, `v` сменился дважды (сохранение сида = 2 запроса), сид в каталоге (1290).
- Регресс: страница сида 12 и `/minecraft-seeds-catalog/` 10 отложенных скриптов, как раньше.

## Находки

- **DEV-670/F1** (Low, наблюдение, решение владельца - упомянуть в комменте): runtime WP Rocket Delay JS на лендинге (`RocketLazyLoadScripts`, в Wayback 04-Nov его нет)
  повторяет первый клик (`_replayClicks`, событие `isTrusted=false` через ~110 мс), если с первого движения мыши / касания прошло < ~150 мс:
  чип фильтра включается и выключается, «Show more» +12. Выбор редакции идемпотентен, не страдает.
- Вне задачи: [DEV-724](https://antihost.atlassian.net/browse/DEV-724) - `&#038;` литералом в 132 названиях карточек finder (`get_the_title()` в `bootstrap.php:123` + `textContent`), с мая.

## Гочи для тестов

- Полного каталога в `window.GodlikeNewSeedCalculator` нет - оракул брать из `catalogUrl` (тот же `?v` → кэш браузера).
- До `data-sc-catalog="ready"` работает только первый экран; `SeedFinder.waitReady()` это ждёт.
- Первый клик без предварительного движения мыши может быть повторён WP Rocket (F1); `waitReady()` двигает мышь, тесты не задевает.
- У страницы `scroll-behavior: smooth`: в пробах координатных кликов ставить `scrollBehavior = 'auto'`, иначе клик мимо.
