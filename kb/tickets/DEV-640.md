# DEV-640 - Wings-колбэки бэкапов только от ноды сервера

> **В двух словах.** Ноды Wings сообщают панели о бэкапах тремя запросами: статус (завершён / провален), конец restore и
> S3-ссылки на загрузку. Панель искала бэкап по uuid во всей базе, и любой ноде хватало своего токена, чтобы завершить или
> провалить бэкап сервера другой ноды, снять `restoring_backup` с чужого сервера или получить ссылки на запись чужого архива
> (IDOR того же класса, что [DEV-580](DEV-580.md), найден при его аудите). Теперь бэкап ищется только среди серверов ноды
> из токена, чужой uuid отвечает 404 как несуществующий. QA: PASS, prod 05-Nov-2026.

## Что изменилось
- [panel!1758](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1758) (бэкенд, влит в master 05-Nov-2026 08:33 UTC).
  Миграций нет, Wings и фронт не менялись.
- `GET /api/remote/backups/{uuid}` (S3-ссылки), `POST /api/remote/backups/{uuid}` (статус), `POST /api/remote/backups/{uuid}/restore`
  ищут бэкап среди серверов, у которых `servers.node_id` = нода из токена (серверы в soft delete тоже).
- Чужой и выдуманный uuid: одинаковый 404 `NotFoundHttpException`, бэкап, `upload_id` и `servers.status` не меняются.
  Каждый отказ пишется в лог панели: `Backup callback refused: no backup with this uuid on the calling node` (`node_id`, `backup_uuid`).
- Бэкапы баз из колбэков убраны (Wings их не шлёт: дамп пишет и восстанавливает сама панель) - uuid бэкапа базы всегда 404.
- Новый сервис `NodeBackupResolver` + `get…OrNullByNodeIdAndUuid` в репозиториях core / instance / folder / World Backup 📖.
  Закомментированная с 2024 проверка ноды в `BackupRemoteUploadController` удалена.

## Как это работает
Колбэки вызывает только Wings с заголовком `Authorization: Bearer <token_id>.<token>` из `config.yml` ноды. У QA этих токенов нет
(`nodes.daemon_token` в БД зашифрован), логов панели тоже, поэтому негатив проверяет разработка.
Принятый риск из MR: колбэк со старой ноды после cutover / rollback трансфера получит 404; restore, шедший в момент cutover, оставит
`restoring_backup` (ранбук в MR: `UPDATE servers SET status = NULL ...` и повторить restore на текущей ноде).
