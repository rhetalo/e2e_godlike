# DEV-583 - Трансфер в админке: локация сервера первой, сортировка по нагрузке

> **В двух словах.** Саппорт переносит серверы между нодами чаще всего внутри одной локации. Раньше модалка Transfer
> показывала локации по алфавиту, а нагрузку нод неверно. Теперь первой идёт локация сервера с бейджем «Current location»,
> ноды отсортированы по реальной нагрузке (Load = максимум из CPU, Mem, Disk), а ноды без свежих метрик стоят в конце
> с «no data». QA: prod PASS 27-Oct-2026, только просмотр, без переносов.

## Что изменилось
- [panel!1702](https://git.godlike.ovh/panel/panel-godlike-host/-/merge_requests/1702) (merged в master 26-Oct-2026, на проде 27-Oct):
  - `GET /admin/servers/view/{id}/manage-transfer` публикует `serverLocationId` и `metricStaleAfterSeconds` (окно свежести, на проде 7200 с);
  - новый `NodeRepository::getNodesForServerTransfer()`: `real_cpu_percent` (среднее за 15 мин до последнего CPU-семпла ноды),
    `real_ram_*` / `real_disk_*` из последнего **полного** семпла в окне свежести (тот же, что берёт балансировщик), `real_age_seconds`,
    `real_load_percent`; null = нет данных, а не «0% нагрузки»;
  - `LoadBalancerMetricRepository::getAverageCpuUtilizationForNodes()` - одним запросом на все ноды;
  - `transfer.js`: сортировка по умолчанию `load`, кнопки Load / CPU / Mem / Disk / Name, null всегда в конце,
    бейдж возраста обновляется раз в 30 с (жёлтый после 5 мин, красный за 25% до конца окна, потом «stale»);
  - `getNodesForServerCreation()` больше не тянет метрики (страница создания сервера их не использовала).
