# DEV-532 - Скрытие дублей модпаков из клиентского каталога

> **В двух словах.** Многие модпаки есть и на CurseForge, и на Modrinth, и клиент видел их в выборе дважды. Теперь
> админ может галочкой в админке убрать любую запись из клиентского каталога, без деплоя. Изменение действует сразу,
> а серверы, которые уже стоят на скрытой версии, продолжают работать и обновляться. QA 08-Oct-2026: PASS.

## Что изменилось
- В `modpacks_v2` новое поле `is_listed`. В админке `/admin/modpacks-v2/view/{id}` чекбокс «Client catalog»
  (колонка Listed / Hidden), сохраняется `PATCH .../listing`.
- Скрытая запись пропадает из клиентского каталога и калькулятора modded-страницы (desktop и mobile); `meta.total` уменьшается.
- Detail скрытого модпака отдаёт 200 с версиями; существующие серверы на нём ставятся и обновляются; админка пулов
  (`/pools/new`) видит скрытую запись.
- Прямая ссылка корзины на скрытый Modrinth-модпак (`modpackId=modrinth:...`) открывается.
- В каталоге модпаков ultra.panel (Source = Modrinth) скрытый модпак находится - как и описано в MR.

## Как это работает
- Применяется на следующий запрос: API `Cache-Control: no-cache`, Cloudflare `DYNAMIC`.
- Скрытие ручное, по одному модпаку; глобального приоритета CF над Modrinth нет (вне скоупа по договорённости с автором).
- Валидация PATCH: пусто / «abc» / 5 -> 422, в БД ничего не пишется.
- Не-админ: страница админки -> 403 (проверил владелец); без сессии GET 403, PATCH 419 (CSRF).
- «Select Modpack» на modded-странице = поле калькулятора; корзина берёт модпак только из `modpackId` в ссылке.
- Гоча админки: клик по чекбоксу через `label[for=modpackIsListed]` (label перехватывает клик).
