# DEV-571 - World Backup без ложного «готово»

> **В двух словах.** Раньше копия мира могла получить «готово» без архива (HEAD на Wings всегда отдавал 401, а код
> считал это подтверждением), а «Continue without backup» удалял мир, пока нода ещё паковала копию: нода дописывала
> её из удаляемых файлов, и ротация сносила предыдущую рабочую копию. Теперь «готово» только после ноды, Continue
> сначала отменяет незавершённые копии, отменённая копия не может стать готовой. QA 19-20 Oct-2026 на stage: PASS.

## Что изменилось
- **Continue without backup** сначала шлёт `POST /servers/{uuid}/world-backups/abandon`: все PENDING и FAILED копии
  сервера → DELETING (ответ `data.abandoned: [uuid…]`), готовые не трогаются. Действие идёт только после 200; при ошибке
  тост «Could not cancel the World Backup, so your action was not started. Please try again.» и диалог для повтора.
- Пока abandon в пути - «Cancelling any World Backup still in progress… Your action continues as soon as that is done.»
- Список копий недоступен → «We couldn't check this server's World Backups…», только Cancel / Continue.
- Отменённая копия держит слот ~30 мин от created_at: повторный create → 409 «A World Backup is already being created
  for this server», `meta.refusal: already_in_progress`; потом исчезает.
- **Права на abandon:** любое из `backups.manage`, `files.write`, `server.reinstall`, `server.change_version`,
  `addons.modpacks` (и root admin); только просмотр / restore бэкапов → 403.
- **Audit log:** `server:world-backup.abandon`, «Unfinished World Backups cancelled by "Continue without backup"»,
  `properties.backups: [{name, uuid, status}]`. Пустая отмена и 403 записи не создают. Free-серверы не логируются.
- Restore незавершённой копии → 400 «This World Backup cannot be restored: it has not completed successfully.», сервер
  не останавливается. Restore = `POST /world-backups/{uuid}/restore`.
- Лимит 0: окна нет, abandon не уходит, `POST /world-backups` → 403 «World Backups are disabled for this server»,
  `meta.refusal: disabled`.
