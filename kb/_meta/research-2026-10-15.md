# Этап 3 - ресерч: публикация, проверки, глоссарий, связанные доки

> **В двух словах.** Главная находка не на GitHub, а у нас: в компании уже есть Confluence, и в нём ~120
> страниц DevOps и поддержки по godlike. KB теперь на них ссылается ([реестр](../registry/external-docs.md)).
> Для публикации KB в Confluence есть готовые утилиты, которые сохраняют наши относительные ссылки и рисуют
> Mermaid, но нужен токен с правом записи. Проверки ссылок оставляем свои, глоссарий перенесён в KB.

## 1. Связанные доки - что уже есть в компании

- Сайт `antihost.atlassian.net` подключён к Jira **и Confluence**; у MCP доступ только на чтение (создать задачу или страницу нельзя).
- Пространства с содержимым: **DevOps** (~100 страниц: ДЦ, ноды Wings, VirtFusion, бэкапы, stage, runbooks, ревью инцидентов) и
  **Antihost Team** (~20 инструкций поддержки: яйца, Docker-образы, порты, FiveM, ARK, Dedicated). Остальные (DEV, L2, MARKETING ...) пустые.
- Новое для KB: продукт **Dedicated Servers** с панелью `baremetal.godlike.host` (страница поддержки), формат эскалации L1 → L2.
- Сделано: [registry/external-docs.md](../registry/external-docs.md) - карта полезных QA страниц со связями на страницы KB.

## 2. Публикация KB: Confluence или Notion

| Критерий | Confluence | Notion |
|---|---|---|
| Уже есть в компании | ✅ `antihost.atlassian.net/wiki`, там DevOps и поддержка | ❓ (упоминается Notion подрядчика по DEV-450) |
| Связь с Jira | ✅ один сайт, смарт-ссылки на тикеты | ❌ отдельно |
| Mermaid | нет встроенного - либо приложение из Marketplace, либо утилита рендерит в картинку | ✅ встроенный блок mermaid |
| Утилиты синхронизации из git | **md2conf** (Hunyadi): обходит папку, превращает относительные ссылки в ссылки на страницы Confluence, рисует Mermaid; **md2cf**: относительные ссылки по флагу, две загрузки на страницу; **mark** (kovetskiy) | **NotionRepoSync** (Sourcegraph): держит индекс страниц, ссылки между файлами переживают обновления; **mdsync** |
| Что нужно от нас | API-токен с правом записи в одно пространство | интеграция Notion с правом записи |

**Рекомендация:** Confluence, отдельное пространство (например `QA` или `KB`), синхронизация `kb/` утилитой md2conf из CI.
Почему: все остальные доки компании уже там, и ссылки из Jira-тикетов на страницы KB будут работать без переходов между сервисами.
Перед выбором проверить на 3-5 страницах: якоря `#находки` и ссылки `../tickets/DEV-xxx.md` превращаются в ссылки на страницы.
❓ Решение и токен - за владельцем; MCP записывать в Confluence не может.

## 3. Проверки KB

| Инструмент | Что умеет | Вывод для нас |
|---|---|---|
| свой `kb/_tools/linkcheck.py` | файлы + якоря по правилам GitHub, 0 зависимостей | **оставляем**, он уже ловит то, что нам важно |
| **lychee** (CLI + GitHub Action) | ссылки, включая внешние, и якоря | можно добавить позже для внешних ссылок (Confluence, GitLab MR) |
| **remark-lint-frontmatter-schema** | проверка front matter по JSON Schema | идея годная, но пакет давно не обновлялся; проще дописать проверку обязательных полей в наш python |

Следующий шаг (по желанию): `kb/_tools/frontmatter_check.py` - у каждой страницы есть `id`, `title`, `status`, `updated`, `verified_on`, `sources`.

## 4. Глоссарий

- Общий подход в docs-as-code: один файл глоссария, термины ссылаются на свою подробную страницу, новые термины добавляются до использования.
  Якоря от заголовков хрупкие (меняются при переименовании), поэтому ссылаемся на **разделы**, а не на отдельные строки.
- Сделано: [kb/glossary.md](../glossary.md) - перенесён `test-docs/glossary.md` (17-Jun) и расширен терминами из KB
  (яйцо, Wings, аллокация, flavor, required_java, is_listed, World Backup, L1/L2 ...), у каждого термина ссылка на «дом».
